# ADR-002 — SQLx offline cache and database provisioning

## Status
Accepted 2026-08-20 by the Product/Architecture owner.

Originally scheduled as a P1-02 follow-up. Pulled into P1-00 because the frozen `check-sqlx`
recipe cannot pass without it — see ADR-001 for the frozen-recipe ruling.

## Context

`final-build-spec.md` §8.2 requires compile-time-checked SQLx queries and states that the
`.sqlx` query cache is committed "so builds are reproducible without requiring a live database
during compilation." It also says to use `sqlx migrate` **from day one**, because retrofitting
migrations onto an evolving schema is harder than starting with them.

The `justfile` and both verify scripts ship a frozen recipe:

```
cargo sqlx prepare --check -- --lib
```

That recipe cannot pass against a workspace with no crates, no migrations, and no query cache.
The open question P1-02 was meant to answer — offline cache versus a live database in CI — had
to be answered now.

SQLite makes the choice unusually easy: a database is a file. There is no server to stand up,
no service container, no credentials, and no network dependency. The usual reason to prefer a
committed cache over live-database CI mostly evaporates.

## Decision

**Commit the `.sqlx` offline query cache, and provision an ephemeral SQLite file for the
operations that need a live database.**

1. `.sqlx/` is generated by `cargo sqlx prepare` and committed. `check-sqlx` is the drift gate:
   it fails when a `query!` changes without the cache being regenerated.
2. The local development database is `target/grid-dev.db` — inside the gitignored build
   directory, disposable, and never committed.
3. `just bootstrap` creates it and applies migrations. `bootstrap` is the documented
   "run once per fresh environment" target and is **not** a verify recipe, so extending it
   does not touch the frozen contract.
4. Migrations are append-only from `0001_schema_meta.sql` onward.

### Required environment contract

`DATABASE_URL` must use the **relative** SQLite URL form. `sqlite://target/…` parses `target`
as a URL authority and resolves to `/grid-dev.db` at the filesystem root, which fails with
SQLite error code 14.

```
DATABASE_URL=sqlite:target/grid-dev.db    # correct: no // authority section
SQLX_OFFLINE                              # unset locally; CI sets true against committed .sqlx
```

A committed `.env` supplies these **only when the variables are otherwise unset** — dotenv
never overrides the real environment. An environment that presets `DATABASE_URL` silently
defeats the `.env` file, which is how this cost a full debugging cycle during P1-00.
`scripts/check-env-contract.sh` therefore asserts the contract and fails loudly by name.

## Consequences

**Easier.** Compilation needs no database. CI needs no service container. A clean checkout
builds offline. Migrations are exercised from the first work package rather than first
appearing in P1-02.

**Harder.** The cache is a generated artifact that must be regenerated and re-committed
whenever a query changes; a contributor who edits a `query!` and forgets will see `check-sqlx`
fail. That is the gate working, not a defect. Reviewers must also read `.sqlx` diffs as
generated output and never hand-edit them.

**Inherited by P1-02.** Domain schema builds on `0002+`. The `schema_meta` table is
infrastructure and does not constrain the domain schema design. Whether `schema_meta` becomes
the real schema-version mechanism or is replaced by a richer versioning table is P1-02's call.

**Cost of the pull-forward.** P1-00's diff is larger than a pure documentation package. The
compensating benefit is that the SQLx toolchain is proven end-to-end before anything depends
on it.

## Compliance

- `cargo sqlx prepare --check -- --lib` in `just verify` — cache drift.
- `scripts/check-migrations.sh` — append-only migrations.
- `scripts/check-env-contract.sh` — the environment contract above.
- `.sqlx/` and `crates/ffi/src/generated/` are listed as never-hand-edit in `CLAUDE.md`.

## Alternatives considered

**Live database in CI, no committed cache.** Rejected: `final-build-spec.md` §8.2 explicitly
requires the cache be committed. It would also make compilation depend on database
availability, which breaks clean-checkout reproducibility (`alpha-spec.md` §9.4).

**Make `check-sqlx` skip when no queries exist.** Rejected by the product owner: verify
recipes are frozen. A gate that passes vacuously is a gate nobody has tested, and it would
have deferred the real failure to whoever wrote the first query.

**Leave `check-sqlx` failing and ship P1-00 red.** Rejected: the work package requires
`just verify` to pass, and a foundational package that ships a known-red gate teaches every
later package that red is acceptable.

**In-memory SQLite (`sqlite::memory:`) for the dev database.** Rejected for the `prepare`
step: the cache generation needs a database that persists across process invocations. Tests
still use per-test temporary databases via `#[sqlx::test]`.
